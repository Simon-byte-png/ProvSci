# ProvSci 下周交流汇报稿

## 一句话目标

我希望实现的不是一个“读论文后给答案”的聊天机器人，而是一个能把论文中的结果挖掘成**有原文证据、有标准字段、有可执行处理路径、能重新验证、能进入数据集或人工复核队列**的科研数据智能体。

## 建议汇报时长与结构

建议准备 15 分钟主汇报、5 分钟原型演示、10 分钟讨论。主线始终围绕三个问题：

1. 这个方向现在做到哪里了？
2. 还缺什么，为什么值得做？
3. 我准备先做出哪个可验证闭环？

## 第 1 页：任务理解与本周产出

### 页面内容

- 任务一：优化综述绘图；
- 任务二：调研数据挖掘与处理智能体的领域现状；
- 任务三：完整定义希望实现的功能；
- 当前产出：领域分类框架、功能蓝图、ProvSci v0.3 原型、benchmark 与下一阶段计划。

### 可以这样讲

> 我没有把三个任务分开做。我的理解是，综述调研先形成结构化比较表，比较表一方面生成综述图，另一方面帮助定位研究空白，最后研究空白决定智能体要实现哪些功能以及先验证什么。

## 第 2 页：问题为什么重要

### 页面内容

- 大量科学结果分散在正文、表格、图和补充材料中；
- 人工整理慢，普通 RAG 主要优化回答，不保证数据可复用；
- 科学数据需要来源、条件、单位、处理过程和许可；
- 错误数据一旦进入数据库或训练集，会被下游反复放大。

### 可以这样讲

> 真正困难的不是把一个数字抽出来，而是证明这个数字对应哪个样本、什么指标、什么实验条件和单位，并且能从原文重新算出同一个答案。所以我把问题定义成“可审计的数据生产”，而不是“文献问答”。

## 第 3 页：领域现状的技术版图

建议画一张六层泳道图：

```text
规则/NLP -> 文档解析 -> 表格/图表抽取 -> 知识图谱
                    -> LLM/VLM 抽取 -> Agent 编排与验证
```

### 讲述重点

- 传统规则稳定但泛化弱；
- GROBID/Docling 等解决“文档结构是什么”；
- 表格和图表工具解决“数据在哪里”；
- 知识图谱解决“如何关联和查询”；
- LLM/VLM 提高长尾语义和多模态适应性，但有幻觉和数值漂移；
- Agent 把检索、解析、抽取、验证和复核串成流程，但很多方案仍缺细粒度 provenance 与可复算路径。

## 第 4 页：现有方案的共同空白

建议只放五个大词，口头解释：

1. **证据不细**：只有论文级引用，没有页码、表格行列或图中数据点；
2. **条件易丢**：数字正确但样本、指标、时间、剂量或统计口径错误；
3. **路径不可复算**：没有保存从证据到答案的中间步骤；
4. **评价偏窄**：只看字段 F1，不看许可、泄漏、重复和人工成本；
5. **失败被隐藏**：低置信和冲突样本没有进入正式复核流程。

### 关键过渡句

> 这五个空白决定了 ProvSci 的差异化定位：不追求让模型说得更像专家，而是让每条结果都能被检查和重放。

## 第 5 页：ProvSci 的目标闭环

建议画主流程图：

```text
文献与补充材料
  -> 统一文档包
  -> 结果候选
  -> 数值/单位/条件标准化
  -> 任务、证据与 acquisition path
  -> 独立 replay 验证
  -> Gold / Silver / Human Review
  -> 数据集、综述图与分析报告
```

### 四条设计原则

- 模型生成候选，不能单独决定真伪；
- 所有转换保留 raw value 和中间值；
- Gold 必须同时有证据和可执行路径；
- 失败样本是正式产物，进入复核队列。

- 完整检索、审核界面、增量数据库和生产部署。

### 汇报原则

明确说“工程原型”和“基线”，不要把计划能力说成已完成。主动暴露限制反而能证明研究问题定义清楚。

## 第 9 页：五分钟演示脚本

1. 打开一个示例文档，指出原始表格/正文结果；
2. 运行 `./scripts/run_demo.sh`；
3. 打开生成的 `all.jsonl`，展示 question、answer、unit 和 evidence；

## 第 10 页：评价方案

### 页面按层次展示

- 字段：P/R/F1、数值误差、单位准确率、条件完整率；

## 老师可能追问与回答思路

### “这和 RAG/文献问答有什么区别？”

RAG 的直接产物通常是回答；ProvSci 的产物是可复用数据样本。样本包含 raw evidence、细粒度定位、标准化字段、处理路径、验证结果、质量等级和许可状态，可以进入数据集、数据库或后续模型训练。

### “为什么一定要 agent？”

如果任务只是固定表格抽取，普通 pipeline 足够。Agent 的价值在于根据文档类型、模态、置信度和失败原因动态选择解析器、抽取器、验证器和复核路径。我的方案会保留确定性 pipeline 作为骨架，只有需要动态决策的环节使用 agent，避免为了概念而 agent 化。

### “LLM 自己复核自己可靠吗？”

不可靠。因此模型复核只作为信号之一。数值、单位、依赖和路径由确定性工具重放；证据充分性可由规则、第二模型和人工抽检组合判断；关键指标用人工 Gold 评估。

### “创新点在哪里？”

潜在创新点不是简单拼接解析器与大模型，而是结果级可执行 provenance：每个样本不仅有引用，还保存可以独立重放的 acquisition path，并把路径复现率、证据精度和数据产出率作为核心评价。最终创新点仍需通过系统综述和 baseline 实验确认。

### “为什么先做表格数值？”

表格结果密度高、证据边界相对明确、可做确定性验证，适合作为最小闭环。它仍包含层级表头、脚注、单位、条件和合并单元格等真实难点；验证闭环成立后再扩展到图和公式风险更低。

### “怎么证明不是 demo？”

使用预先冻结的真实开放文献集，进行文献级 train/dev/test 隔离；公开任务 contract 和标注规范；报告所有失败与人工成本；与规则、单次 LLM、不同解析器做消融；保证 benchmark 可一键重跑。
