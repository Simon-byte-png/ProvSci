# ProvSci 下一阶段要求

> 这份文档把会议要求和当前仓库状态合并成一份可以直接执行的项目要求。它只描述 ProvSci 这条“科学结果数据智能体”线，不把钙钛矿公司项目算作本项目的默认方向。

## 1. 项目要解决的问题

ProvSci 不做一个什么问题都能回答的通用科学智能体，而是做一个垂直领域的数据结果处理系统：

> 从可靠的科学文献或公开数据源中找到结果数据，保留原始证据和获取路径，把结果整理成机器可读的结构化数据，并检查这个结果能不能被重新验证。

最终交付的不只是一个答案，还包括：

- 结构化结果；
- 原始来源和证据位置；
- 数据对应的条件、单位和上下文；
- 数据是如何抽取、转换或计算出来的；
- 验证是否通过，以及没有通过的原因；
- 数据质量等级和许可信息。

## 2. 当前范围和明确边界

### 2.1 第一版范围

第一版选择一个明确的垂直领域，优先沿用仓库当前设定的“生物医学剂量—效应 / 浓度数据”，例如 IC50、EC50、浓度、时间点和组间差异。领域必须在开始大规模开发前冻结，不能同时覆盖整个生物学、材料学和药物研发。

### 2.2 第一版暂不做

- 通用型科学智能体；
- 自动化实验设备控制；
- 企业私有数据接入；
- 钙钛矿分子数据库建设；
- 只凭模型记忆生成没有证据的数据；
- 直接训练 6B/7B 模型；
- 一开始就处理所有图像、复杂流程图和所有文档类型。

图像和复杂多模态解析可以作为后续扩展，但不能因此拖住第一版的文字、表格和数值结果链路。

## 3. 第一版必须具备的能力

### 3.1 文档和来源

- 接收 PDF 和 HTML 文档；
- 记录 DOI、URL、文档版本和文件 hash；
- 区分正文、表格、图注、补充材料和数据库记录；
- 对来源做基本可靠性检查；
- 原始论文默认不直接提交到公开仓库，避免版权问题。

### 3.2 结果数据抽取

- 从正文和表格中识别目标结果；
- 抽取数值、单位、条件、样本或分子名称；
- 保留表格编号、行列位置、页码或文本片段；
- 处理单值、多值、范围、上下限、均值和误差等表达；
- 识别“没有报告”与“模型没有找到”的区别；
- 将不同表达归一到固定 schema。

### 3.3 任务和获取路径

- 将候选结果改写成 lookup、QA、计算或关系任务；
- 只允许路径调用白名单工具；
- 记录每一步工具、参数和输出；
- 对单位换算、算术计算等确定性操作使用程序完成；
- 不允许模型直接编造最终数值。

### 3.4 验证和质量分层

- 按记录的路径重新读取证据并重算结果；
- 检查答案和验证值是否一致；
- 检查单位、条件和证据是否匹配；
- 对冲突、歧义和缺字段结果标记原因；
- 将结果分为 raw、silver、gold 三个等级；
- gold 数据必须经过人工核验或有足够强的独立验证证据。

### 3.5 交付格式

每条结果至少要能生成一张 ResultCard，包含：

```text
问题 / 结果 / 单位 / 条件
来源 / 证据位置 / 原文片段
任务类型 / 工具路径 / 验证结果
质量等级 / 许可 / 备注
```

最终可以同时输出 JSON、CSV 和面向用户查看的页面。知识图谱或关系网络属于后续交付形式，前提是基础结果卡已经稳定。

## 4. 评测要求

项目不能只展示 Demo，必须建立一套固定测试集。

测试集至少包含：

- 一批人工核验的 gold 样本；
- 一批保留原始来源的普通样本；
- 不同文档格式；
- 单值、多值、单位换算、条件依赖和表格定位题；
- 正常样本、歧义样本、错误来源样本和无法回答样本。

需要报告：

- 候选发现率；
- 结果抽取准确率和召回率；
- 证据定位准确率；
- 单位和条件匹配率；
- 路径验证通过率；
- raw 到 silver、silver 到 gold 的通过情况；
- 单题 token、调用次数、耗时和失败原因。

论文级结果还需要和至少一个现有方案或简单基线比较，并做关键模块的消融实验。目标不是口头声称 SOTA，而是找到一个具体空白，在这个空白上取得可复现的优势。

## 5. 当前代码对应的完成状态

目前仓库处于“架构和接口骨架”阶段：

- 已有 `ResultCard`、`EvidenceSpan`、`PathStep` 等类型；
- 已有白名单工具名称；
- 已有 `ingest → extract → claims → path → verify → gate` 的目录和流程设计；
- 已有 `provsci status` 命令；
- 已有 schema 的基础测试；
- 尚未实现真实 PDF/HTML 导入；
- 尚未实现文字、表格和结果抽取；
- 尚未实现候选事实发现；
- 尚未实现真实路径生成和重跑验证；
- 尚未实现质量闸门、数据卡批量生成和用户界面；
- 尚未形成可用于论文的固定 Benchmark 和结果表。

所以当前项目不是“功能基本完成”，而是已经把方向、字段和模块边界搭好，下一步要从接口骨架进入最小可运行链路。

## 6. 下一阶段执行顺序

### P0：冻结项目边界

- 确定一个非钙钛矿的垂直领域；
- 冻结第一版字段和 ResultCard schema；
- 准备第一批人工核验样本；
- 写清楚什么算正确、什么算未知、什么算失败。

### P1：先跑通一条最小链路

完成：

```text
一篇 PDF/HTML
→ 文本或表格结果
→ 证据定位
→ 结构化 ResultCard
→ 程序验证
→ gold/silver/raw 判断
```

这一步先不追求通用性，要求结果可重复、失败原因可查看。

### P2：补齐数据智能体功能

- 增加来源发现和文件获取；
- 增加多格式解析；
- 增加候选结果筛选；
- 增加歧义修复和人工复核入口；
- 增加批量处理；
- 增加 CSV/JSON/数据卡导出；
- 增加日志、统计和错误样本收集。

### P3：建立可对比的实验

- 固定测试集和评测脚本；
- 选择一到两个具体研究空白；
- 对比基础 LLM、简单规则方法和已有专用工具；
- 做关键模块消融；
- 整理失败案例和适用边界。

### P4：决定论文形态

根据实验结果二选一：

- 方法论文：重点写抽取、验证、路径和修复方法；
- 数据库论文：重点写数据规模、质量、字段、来源、可检索性和数据价值。

如果没有明显方法创新，就不要把“代码很多”当成论文创新；如果没有足够规模和质量的数据，也不要把普通导出文件包装成数据库论文。

## 7. 和会议中其他工作的关系

### 7.1 综述

由朱兴宇继续修改、补图和选择期刊。它不作为 ICLR 2027 的主投稿任务，先把文章打磨到可以正式投稿的程度。

### 7.2 长程状态维护算法

由金若凡先推进核心算法设计。朱兴宇在方案确定后配合前作复现、代码接入、Benchmark、对比实验和消融实验。会议中提到的图结构、三类依赖图和状态维护指标属于算法论文的研究设想，不是 ProvSci 第一版必须实现的模块。

### 7.3 钙钛矿和公司案例

钙钛矿合成、企业生产设备和私有数据属于另一个应用方向。它可以作为未来数据形态和长链条过程记录的参考，但不默认作为朱兴宇当前数据智能体的领域任务。

## 8. 最终成功标准

ProvSci 达到下一阶段目标时，应当满足：

1. 用户给一篇真实公开论文，系统能完成一次端到端结果抽取；
2. 输出的每条数据都有来源、证据位置、条件和单位；
3. 系统能说明数据是直接读取、换算得到，还是无法确认；
4. 关键结果能按记录的路径重新验证；
5. 错误和歧义不会被静默写进高质量数据集；
6. 批量测试结果可以和基线比较；
7. 代码、样例、评测脚本和结果可以让别人复现；
8. 最终能据此判断应该投方法论文、数据库论文，还是继续做产品。

达到这个标准，才算从“有系统架构 Demo”进入“有实际验证价值的专用数据智能体”。
