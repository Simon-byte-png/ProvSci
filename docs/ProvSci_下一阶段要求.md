# ProvSci 下一阶段要求

这份文档只对应你负责的 ProvSci 数据结果智能体，不把钙钛矿分子、公司生产设备和长程状态维护算法的核心研究算成 ProvSci 第一版任务。

## 一句话目标

把公开科学文献中的结果数据，变成带来源、证据、条件、单位、处理路径和验证状态的结构化数据，而不是只生成一段看起来合理的回答。

## 现在仓库已经做到哪里

当前仓库已经是 **v0.3 工程原型**，不再是只有目录和接口的骨架。已经具备：

- JSON、CSV、TSV、HTML、Markdown、纯文本、XLSX、JATS 等输入适配器，以及 `pdftotext` PDF 基线；
- 文档分段、结果相关 section 路由、表格数值/文本/关系候选挖掘；
- 数值与单位解析、均值±误差解析、单位换算；
- 任务、证据和 acquisition path（从证据得到结果的可执行步骤）生成；
- 白名单工具、确定性 verifier（重新执行并检查结果的验证器）；
- raw / silver / gold 质量分层、人工复核输出、批处理和 JSONL 导出；
- 文献级数据切分、严格 benchmark、CLI 和端到端测试；
- 本地 fixture、真实 CC-BY PMC/JATS 文献、演示脚本和评测脚本。

目前的 benchmark 已经能证明“流程可以跑通”，但数据规模还小，复杂 PDF、图片/曲线、外部来源获取、人工审核界面和大规模领域数据还没有完成。因此，当前准确定位是：**可审计的结果数据智能体原型**，还不是成熟产品或通用科学家智能体。

## 你接下来要做的事情

### P0：把当前原型做成可汇报、可复现的版本

1. 选定一个非钙钛矿的具体数据子领域，并冻结第一版字段和 ResultCard schema。
2. 用真实、许可清晰的公开文献扩充人工核验样本，记录正确结果、证据位置、条件、单位和失败原因。
3. 重新跑通 demo、benchmark 和 real-smoke，整理一张当前结果表和一组典型失败案例。
4. 做出一次从文献输入到 Gold/Silver/Human Review 输出的完整演示，确保别人按 README 能复现。

### P1：补齐数据智能体的核心缺口

1. 提升 PDF、表格、图注和补充材料的解析能力；复杂版面接入可替换的 Docling/GROBID/TATR/Nougat 等适配器。
2. 补充可靠来源发现、文件获取、DOI/URL/版本/hash 和许可信息记录。
3. 扩大候选结果类型：实验条件、文本关系、补充材料和必要的图文结果。
4. 增加歧义修复、重复检测、冲突标记、失败重试和人工复核入口。
5. 增加批量处理、结果检索、CSV/JSON/数据卡导出，并为后续知识图谱保留实体—关系—证据结构。

### P2：形成论文或产品判断依据

1. 固定测试集，报告抽取准确率/召回率、证据定位、单位和条件匹配、验证通过率、Gold 比例、成本、耗时和失败类型。
2. 和规则基线、基础 LLM 或一个现有专用工具做对比，并对证据、验证、质量门禁等模块做消融。
3. 根据数据规模、质量和实验结果决定交付形态：方法论文、数据库论文，或先作为可演示的专用数据产品继续迭代。

## 数据必须达到的要求

每条进入 Gold 的结果至少要有：

```text
结果 / 单位 / 条件
来源 / 证据位置 / 原文片段
任务类型 / 处理步骤 / 可执行路径
验证状态 / 质量等级 / 许可信息
```

不能确认的结果不能硬塞进 Gold，要进入 Silver 或 Human Review，并保留失败原因。最终测试不能只看答案像不像，还要看证据是否支持、条件是否对应、路径能否重跑、同一篇文献是否发生数据泄漏。

## 和会议中其他任务的边界

- **综述文章**：你负责继续修改、补图、完善现状分析并选择期刊投稿。它是独立论文任务，不是 ProvSci 的验收条件。
- **长程智能体状态维护算法**：学姐负责核心研究方案，包括图结构、规范图/行为图/观测图和状态依赖维护。方案确定后，你配合代码复现、Benchmark、对比实验和消融实验；不需要现在把这套算法并入 ProvSci。
- **钙钛矿与公司生产设备**：是另一条应用方向，不是你当前 ProvSci 的默认数据领域，也不应直接写成你的个人待办。

## 最终达到什么状态才算完成

用户给一篇真实公开文献后，ProvSci 能稳定完成：

```text
文献导入
→ 结果候选发现
→ 证据定位
→ 结构化数据卡
→ 处理路径记录
→ 程序验证
→ Gold / Silver / Human Review 分流
→ 可检索、可导出的结果
```

同时，代码、样例、评测脚本和结果表可以让别人复现；系统会明确告诉使用者哪些数据可信、哪些数据需要人工确认、哪些问题暂时无法回答。到这一步，才算从“能跑的 Demo”进入“有实际数据价值、可以支撑论文或产品决策的专用智能体”。
