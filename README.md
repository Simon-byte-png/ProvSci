# ProvSci：可验证的科学结果数据智能体

ProvSci 的目标不是做一个“什么都能回答”的通用科学智能体，而是把公开科学文献里的结果数据整理成可以复核、可以重跑、可以继续使用的数据。

它交付的不是一句模型答案，而是一张带证据的数据卡：

1. 结果是什么；
2. 来源在哪篇文献、哪一页、哪张表或哪一格；
3. 结果对应哪些条件和单位；
4. 结果是直接抽取、换算还是计算得到；
5. 验证能不能重新跑通；
6. 数据属于 raw、silver 还是 gold 质量等级。

## 当前状态

当前版本是 **0.1.0 架构骨架**，已经完成方向、模块边界、结果数据卡字段和白名单工具设计，但还没有完成真正的数据智能体。

已经有：

- `ResultCard`、`EvidenceSpan`、`PathStep` 等基础数据结构；
- `ingest → extract → claims → path → verify → gate` 流程目录；
- `provsci status` 状态命令；
- 白名单工具名称；
- schema 基础测试；
- 结果数据智能体的现状、竞品、评测和可信数据设计文档。

还没有：

- 真实 PDF/HTML 导入；
- 正文、表格和数值结果抽取；
- 候选事实发现；
- 可执行的数据获取路径；
- 程序化重算和验证；
- raw/silver/gold 质量闸门；
- 批量数据卡生成；
- 可用于论文的固定 Benchmark 和对比结果。

因此，当前仓库应被理解为“从研究设想进入最小可运行系统之前的工程骨架”。

## 第一版做什么

第一版只选择一个明确的垂直领域。仓库当前暂定为生物医学剂量—效应 / 浓度数据，例如 IC50、EC50、浓度、时间点和组间差异；正式开始批量开发前还需要把领域和字段冻结。

第一版优先处理文字和表格中的结果，不同时追求全学科、复杂图片理解和实验设备控制。大模型可以帮助发现候选数据，但不能只凭记忆生成没有证据的答案。

第一版的最小可运行链路是：

```text
一篇公开论文
    ↓
文档导入（页码、来源、hash）
    ↓
文字 / 表格 / 数值结果抽取
    ↓
候选事实和任务
    ↓
白名单工具路径
    ↓
程序重算与验证
    ↓
质量分层
    ↓
结果数据卡（答案 + 证据 + 条件 + 路径 + 日志）
```

## 仓库结构

```text
docs/                 定位、功能设计、调研
src/provsci/          Python 包（当前是接口骨架）
  ingest/             文档导入
  extract/            表格与文本抽取
  claims/             候选事实发现
  path/               获取路径生成
  verify/             路径验证器
  gate/               质量闸门
  schema.py           数据卡 JSON 结构
data/
  raw/                原始论文（默认不入库）
  gold/               人工核验样本
  cards/              自动产出的数据卡
tests/
```

## 本地启动

```bash
cd ProvSci
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env   # 填入 XAI_API_KEY
```

后续模型调用计划通过 xAI API（环境变量 `XAI_API_KEY`）接入。当前命令行还没有真实调用模型，只会打印流水线状态；不要把真实密钥写进 Git。

## 下一阶段目标

下一阶段不是继续堆一个展示型 Demo，而是完成一条可验证的最小链路：

```text
真实 PDF/HTML
→ 结果数据
→ 证据定位
→ 结构化 ResultCard
→ 程序验证
→ gold/silver/raw 判断
→ 固定测试集上的可量化结果
```

验收时，系统至少要能对真实公开论文完成一次端到端抽取，并为每条结果保留来源、证据、条件、单位和获取路径。还要能报告抽取准确率、召回率、证据定位准确率、验证通过率、调用成本和失败原因。

完整要求见：[ProvSci 下一阶段要求](docs/ProvSci_下一阶段要求.md)。
